# 雀魂三人麻将段位规则基线与来源

## 适用范围

本文件与 [三人麻将差异 SKILL](../13-sanma/SKILL.md) 默认讨论**雀魂三人麻将段位场**；友人房“无自摸损”仅在明确标注的选项对照中讨论。它不覆盖雀魂四人麻将段位场，也不直接代表其他比赛房、自定义房或其他平台的三麻设定。

四人麻将规则请见 [四麻规则基线](rules-sources.md)。三麻与四麻共通的定义（和牌型、立直、振听、符的构成等）可引用四麻章节；涉及人数、牌组、北拔、宝牌、支付、流局或终局时，必须以本文件为准。

## 来源与维护原则

核验优先顺序：

1. 雀魂客户端三人麻将段位场的规则、结算和房间说明。
2. 雀魂官方网站、公告或帮助中心的三人麻将说明。
3. 本仓库三麻章节与示例。

每次客户端规则变动时，先更新本文件，再更新 `13-sanma/SKILL.md` 和相关示例。未核验项目不得伪装为固定平台规则。

2026-10-07公开资源核验见 [核验记录](verification-2026-10-07.md)。下表区分既有基础结论、用户确认和本次官方公开说明；本次没有进行服务器实战结算测试。

| 自摸损与流局满贯支付 | 公开说明＋用户确认 | 段位场自摸和已成立的流局满贯均按四麻标准计算，再去掉不存在的北家支付部分，不转嫁给另外两家 |
| 开放断幺九 | 公开说明已核验 | 三麻段位场允许副露断幺九 |

| 排名与同点 | 用户确认；未作服务器实测 | 先按点数从高到低排名，同点按整场开局时东、南、西顺序；三麻没有北家 |
| 本场 | 用户确认 | 每本总额`(3-1)*100=200`；荣和由放铳者支付，自摸两名对手各支付每本100点；n本乘n |
| 荒牌罚符 | 用户确认 | 总额`(3-1)*1000=2000`；1人听牌时两名未听者各付1000，2人听牌时未听者向两名听牌者各付1000，0人或3人听牌不收付 |
| 无人和牌终局的供托 | 用户确认 | 全部归结算顺位为1的玩家；同点按整场起家顺序判定 |
| 杠宝牌时序 | 用户确认 | 暗杠通过抢杠判定后先翻指示牌、再摸岭上；大明杠／加杠在摸牌后下一步非和牌操作后翻指示牌，见第9章 |
| 荒牌流局推进与本场 | 用户确认 | 同四麻：庄家听牌连庄、未听流庄；荒牌流局本场加1，供托保留。东3起家西家坐庄，流庄且对局继续时进入南1，起家东家重新坐庄；南3／西3类推 |
| 途中流局 | 用户确认共通处理 | 同四麻的共通条件及连庄、本场加1处理；不设四风连打、四家立直，也不替换成三风连打、三家立直。九种九牌、四杠散了见第7章；第四杠完整优先级另待交叉验证 |
| 流局满贯成立 | 四麻条件公开配置核验；三麻适用用户确认 | 同四麻：荒牌流局时自己的舍张全为幺九牌且未被他家吃碰杠；拔出的北不属于牌河，不参与判定 |
| 多家流局满贯支付 | 用户确认 | 各成立者分别按满贯自摸计付，并考虑自摸损；两家成立时，第三家分别承担对两家的满贯自摸支付，成立者之间等额支付抵消；0本场示例见计分实例 |
| 流局满贯后续流程 | 用户确认 | 按荒牌流局处理，仅点数改按满贯自摸结算，不再叠加荒牌听牌罚符；庄家听牌连庄、未听流庄，本场加1，供托保留（若整场终局则按终局供托规则分配） |
| 累积役满 | 用户确认同四麻 | 13番及以上固定单倍役满，26番或更高不增加倍数，不与自然役满复合；多个自然役满仍按倍数累计 |
| 切上满贯 | 用户确认同四麻 | 不采用；4番30符、3番60符仍按通常公式，三麻自摸支付再去掉北家份额 |
| 包牌范围与触发 | 用户确认同四麻 | 仅大三元、大四喜；最后一次碰或大明杠使该役满确定的舍牌者成为责任者，暗杠不触发；只转移包牌役满部分，不转移无关部分 |
| 自摸包牌金额 | 用户确认；未作服务器实测 | 先按四麻理论自摸支付去掉北家份额，再由责任者独自支付实际总额。单倍役满子家24000、庄家32000；大四喜按双倍为子家48000、庄家64000，均不含本场与供托 |
| 荣和包牌金额 | 用户确认；未作服务器实测 | 荣和不扣自摸损，责任者与放铳者不同则各支付包牌役满部分的一半；放铳者另付非包牌部分。子家大三元总额32000，责任者与放铳者各付16000 |

### 友人房选项（不作为段位场默认）

用户确认：开启“无自摸损”时，四麻理论上北家应支付的点数由实际另外两家平摊均分；自摸与流局满贯的支付据此调整。对应示例见 [三麻计分实例](example-scoring.md)。此选项与段位场的有自摸损规则分别维护。

## 平台差异警告

三麻在北拔、北牌是否保留役牌属性、赤牌枚数、累积役满、切上满贯、自摸支付和终局条件上常有平台差异。写作采用本文件标明的已核验或用户确认结论；待核验项目实战以雀魂客户端当前规则与结算结果为准。
